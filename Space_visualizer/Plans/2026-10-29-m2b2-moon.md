# M2b.2 The Moon Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

Back to [[Home]] · Spec: [[2026-10-29-m2b2-moon-design]] · Session: [[2026-10-29-session-m2b2-moon]]

**Goal:** add the Moon as a selectable, accurately placed, cited and well-shaded body, and move Earth off the Earth–Moon barycentre.

**Architecture:** a new orbit variant (`satellite`) whose geocentric position comes from a Chebyshev table fitted to JPL Horizons vectors (1800–2050) with JPL mean elements as the fallback; a new pure `systemState` computes every body for one date, parents first, and applies the barycentre split to Earth. The pipeline builds the table and the Moon's facts, details and imagery the same way as the planets; the scene hides moons that would overlap their parent in readable scale.

**Tech Stack:** TypeScript, Zod, Vitest, React Three Fiber / three.js (GLSL), Zustand, Playwright (SwiftShader), sharp, tsx.

**Spec:** `Space_visualizer/Specs/2026-10-29-m2b2-moon-design.md`. Executors read it first.

## Global Constraints
- Official sources only, each value cited; curated values keep the exact sentence they came from. No Wikipedia or aggregators.
- `src/core` stays pure: no React, three.js or Zustand imports; `zod` only.
- Frame and units everywhere in core: heliocentric (or geocentric for the Moon table) **ecliptic J2000, km, TDB Julian dates, float64**.
- Moon table: maximum held-out error **≤ 1 km**; committed file **≤ 2 MB** (spec said 1.5 MB; raised in Task 3's ruling if the fit needs it, see Task 3 Step 6).
- Barycentre: `μ = GM_Moon / (GM_Earth + GM_Moon)` from NAIF `gm_de440.tpc`; Earth = EMB − μ·r; Moon = Earth + r.
- Illustrative visuals (earthshine, eclipse tint, relief exaggeration) are labelled illustrative in the drawer.
- Plain, short sentences in user-facing text.
- Every commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Stage only the files the task names; **never stage** the uncommitted cloud-setup files (`CLAUDE.md`, `.claude/`, `scripts/`, `Space_visualizer/Cloud sessions.md`, the cloud plans and the 2026-10-16/2026-10-29 vault-check session notes, and the cloud edits to `Changelog.md`, `Home.md`, `Start here.md`; vault edits by this section go in Task 11, staged with `git add -p`).
- Never run two Playwright runs at once. Stop only processes you started.

## Review Focus
1. **Segment boundaries and table edges:** a date exactly on a segment boundary, the first and last instant of the table, and one second outside it must give a finite position with no jump > 1 km (Task 1 and Task 2 tests).
2. **Dates far outside 1800–2050** (−4712 and 9999, the app's clamp): the Moon must still have a finite position from the mean elements and the bottom bar must read the right status, never NaN (Task 2 test).
3. **Readable scale when zoomed out:** the Moon must disappear before it sits inside Earth's inflated sphere, and its label must not reappear through the declutter pass (Task 6 test).
4. **Selecting the Moon while it is hidden** (for example from the URL `target=moon` at overview distance): the camera must fly to it and it must show once the separation is large enough; no stuck hidden state (Task 6 test).
5. **Catalogue load failure of the ephemeris file** (404 or a schema error): the app shows the existing data-error screen with a message naming `ephemeris/moon.json`, not a blank scene (Task 5 test).

### Task 1: Chebyshev table schema and evaluator

**Files:**
- Create: `src/core/ephemeris/chebyshev.ts`, `src/core/ephemeris/chebyshev.test.ts`
- Modify: `src/core/catalog/schema.ts` (add `ChebyshevFileSchema` and type `ChebyshevFile`)

**Interfaces:**
- Produces:
  - `ChebyshevFileSchema` / `type ChebyshevFile = { schemaVersion: 1; bodyId: string; centreId: string; frame: 'ecliptic-j2000'; unit: 'km'; sourceId: string; startJdTdb: number; segmentDays: number; degree: number; segments: number[][] }`. Each segment is a flat array of `3 * (degree + 1)` numbers: x coefficients, then y, then z. Refinements: `segments.length >= 1`, every segment has length `3*(degree+1)`, all numbers finite, `segmentDays > 0`, `degree` an integer in [1, 30].
  - `chebyshevRange(file: ChebyshevFile): { fromJdTdb: number; toJdTdb: number }` (to = start + segments × segmentDays).
  - `evaluateChebyshev(file: ChebyshevFile, jdTdb: number): Vec3 | null` — `null` outside `[from, to]`. Segment index `k = min(floor((jd − start)/segmentDays), n − 1)` (so `jd === to` uses the last segment); `τ = 2(jd − start − k·L)/L − 1`; Clenshaw recurrence per axis.

- [ ] **Step 1: Write the failing tests** in `chebyshev.test.ts`:
  - `evaluates a known polynomial`: a 1-segment file, degree 2, x coeffs `[1, 2, 3]` → at τ = 0.5, x = 1 + 2·0.5 + 3·T2(0.5) = 1 + 1 + 3·(−0.5) = 0.5. Same for y, z with other coefficients.
  - `picks the right segment and maps τ`: a 2-segment file where segment 0 is constant 10 and segment 1 is constant 20; at `start + L − 1e-9` → 10, at `start + L` → 20.
  - `includes the last instant and rejects outside`: `jd === to` → finite; `to + 1/86400` → `null`; `start − 1/86400` → `null`.
  - `schema rejects a segment of the wrong length` and `schema rejects a non-finite coefficient` (`ChebyshevFileSchema.safeParse(...).success === false`).

  - `PlanetApproxOrbitSchema` gains `centreCheck: HorizonsCheckSchema.optional()` (Earth only: composed Earth vs Horizons body 399).
  - `SatelliteOrbitSchema`:
    ```ts
    { type: 'satellite',
      table: { file: string /* path under data/, e.g. 'solar-system/ephemeris/moon.json' */, sourceId, validFromJdTdb, validToJdTdb, horizonsCheck: HorizonsCheck },
      meanElements: { sourceId, epochJdTdb, aKm, e, argPeriDeg, meanAnomalyDeg, iDeg, nodeDeg, siderealPeriodDays, apsisPeriodYears, nodePeriodYears, validFromJdTdb, validToJdTdb, horizonsCheck: HorizonsCheck.optional(), note: string },
      barycentre: { massRatio: SourcedValue } | null }   // massRatio.value = μ
    ```
    `OrbitSchema` adds it to the union. Satellite bodies must have a non-null `parentId` (refine on `BodySchema`).
  - `meanElementsGeocentricKm(m: SatelliteOrbit['meanElements'], jdTdb: number): Vec3` with, for `Δ = jd − epoch` days and `Y = 365.25`:
    `node = nodeDeg − 360·Δ/(nodePeriodYears·Y)`; `ϖ = nodeDeg + argPeriDeg + 360·Δ/(apsisPeriodYears·Y)`; `λ = nodeDeg + argPeriDeg + meanAnomalyDeg + 360·Δ/siderealPeriodDays`; `M = λ − ϖ`; `ω = ϖ − node`. (Node regresses; apsis advances; mean longitude moves at the sidereal rate.)
  - `satelliteGeocentricKm(orbit: SatelliteOrbit, tables: ReadonlyMap<string, ChebyshevFile>, bodyId: string, jdTdb: number): { r: Vec3; tableId: 'horizons-chebyshev' | 'mean-elements'; inValidRange: boolean }` — Chebyshev when the table is loaded and covers the date; otherwise mean elements, `inValidRange` true inside `meanElements.valid*`.
  - `systemState(bodies: readonly Body[], tables: ReadonlyMap<string, ChebyshevFile>, jdTdb: number): Map<string, BodyState>` — non-satellites via `bodyState`; then each satellite: `r` from above; if its `barycentre` is non-null and its parent's orbit is `planet-approx` with `represents: 'earth-moon-barycenter'`, parent position becomes `EMB − μ·r`; satellite position = parent position + r. A satellite whose parent is missing throws `Error('satellite "<id>" has no parent "<parentId>" in the catalogue')`.
  - `validityStatus(bodies, jdTdb)` (signature unchanged): a satellite inside its table range is `high`; inside its mean-elements range is `extended`; outside both is `out-of-range`.

### Tuned shading values (Task 10)
- Moon `lommelSeeliger` 0.9 to **1** (pure Lommel-Seeliger gives an evenly bright full Moon).
- The rocky shader uses the relief normal for mu, so the BRDF cancels the relief at zero phase. This also touches Mercury (0.85) and Mars (0.4); golden 0-mars is unchanged in look.
- Moon `normalStrength` 1 and the x2 LOLA relief unchanged (R5 not used).
- `EARTHSHINE` = { max **0.02**, color (0.62, 0.72, 0.90) }. The real ratio is about 1e-4; 0.04 made the night side look like a lit blue disc. Strength = max x (1 + cos phi) / 2.
- `ECLIPSE_TINT` = { color **(1.0, 0.30, 0.08)**, amount 0.9, floor **0.12**, centreDarkening **0.5** }. Floor and colour were raised from 0.05 and (1, 0.36, 0.14) so the red wins over the cinematic fill's blue.
- Atmosphere shells multiply in-scatter by `eclipseFactor` at the view path's midpoint.
- Golden camera for 6d: az 2.7, el 24, dist 15000 (about 20 deg off the anti-Sun line, so the shadow clears the info panel).
